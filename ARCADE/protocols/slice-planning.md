# Protocol: Slice Planning

A production slice is a playable increment, not a bundle of code tasks.

## Every slice must define

- Goal
- Player-visible result
- Included scope
- Excluded scope
- Required design work
- Required code work
- Required UX/UI work
- Required art/assets or placeholders
- Required audio/VFX or placeholders
- Required content
- Required integration work
- Required validation work
- Required documentation work
- Risks
- Human validation questions

## Required human questions

1. Are there too many or too few slices?
2. Should any slice happen earlier?
3. Should any slice be merged, split, or removed?
4. Is the first slice the correct first playable target?
5. Is there a technical, visual, content, or UX risk that should be moved earlier?

## Rule

Do not finalize detailed task breakdown until the slice strategy is approved or explicitly accepted by the human.
